# Project Statistics

Approved in chat: the Cards mockup, six all-time project metrics, GitHub Pages frontend, Cloudflare Workers + D1 collector on the Free plan, approximately 1,000 daily visitors. The user requested implementation on 2026-10-18.

- Show Total Visits, Unique Visitors, Databases Loaded, Hands Processed, Files Imported, and Data Processed below the dashboard, including before an import. Show actual version and build date. Missing configuration or an unavailable collector displays unavailable values, never demo numbers or invented zeroes.
- Histories stay on-device. Send only a random browser identifier, stable event identifier, event timestamp, event type, and the numeric import totals. Never send filenames, source hashes, poker identifiers, financial results, cards, or history text. Provide a persistent usage-sharing switch.
- Count visits as sessions separated by 30 minutes of inactivity. Count a completed, successful selection of one or more files as one database loaded. Reimporting the same files is another import. Count the accepted unique hands in each completed import, independently of dashboard filters.
- Use a small Worker API: POST /events for strict, bounded events and GET /statistics for public aggregates cached for five minutes. Restrict browser origins, rate-limit ingestion, and keep D1 access private to the Worker. Do not require accounts or secrets in the frontend.
- Store aggregate counters and browser identifiers; retain event identifiers only for replay protection. A SQLite transaction and triggers apply each accepted event once. Reject conflicting reuse of an event identifier. Expire events after eight days and accept timestamps at most seven days old or five minutes in the future.
- Telemetry is optional infrastructure: timeouts, quota exhaustion, offline operation, blocked storage, malformed responses, cancelled imports, and parser failures must not affect poker analysis. Retries reuse event IDs and have bounded queues and retry counts.
- Verify the actual SQL with SQLite tests, client behavior with controlled storage/network/time, browser import and failure paths, desktop/mobile layouts, type checking, the full existing unit suite, production build, and a local Workers/D1 smoke test. Cloud deployment needs an authenticated Cloudflare account; do not claim the collector is live without a successful deployment.
